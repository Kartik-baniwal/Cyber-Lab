The Problem

Cybersecurity Training is Broken

🚫
Infrastructure Overhead

Complex Setup

Traditional cyber labs require expensive dedicated hardware, complex VM setups, and hours of configuration before a student can even type their first command.

💸
Cost Barrier

Expensive Platforms

Existing platforms like TryHackMe or HackTheBox cost $14–$84/month per user and require constant internet connectivity to remote VM farms.

📉
Poor Progress Tracking

No Audit Trail

Students lose their command history, terminal output, and evidence of completed objectives when a session ends — no proof of work or skill tracking.

🔒
No Isolation

Shared Environments

Shared lab environments contaminate results and create security risks. Every operator needs a fully isolated, ephemeral sandbox — no exceptions.

03 / 12
The Solution

Cyber Lab — One Platform, Everything

  • 🐳
    Ephemeral Docker ContainersEach operator gets a fully isolated, dedicated container spun up in seconds. Zero config, zero persistence, zero contamination.
  • ⌨️
    Live PTY Terminal via xterm.jsReal bash shell — not simulated. Keystrokes stream directly to the container's stdin over WebSocket in real-time.
  • 🐉
    Kali Linux XFCE Desktop in BrowserInteractive draggable windows, terminal, file manager, text editor, browser — the full Kali environment rendered in vanilla CSS/JS.
  • 🚩
    Dynamic HMAC-Signed CTF FlagsEvery session gets a unique, cryptographically signed flag — preventing sharing and validating genuine skill demonstration.
  • 💾
    Complete Audit TrailCommand history, terminal scrollback, objectives, and captured flags — downloadable as a rich .txt transcript at any time.

Deployment Options

From Laptop to Production in Minutes

Option A — Local Dev
$ git clone github.com/Kartik-baniwal/Range_Forge $ cd Range_Forge/backend && npm install && npm run build $ cd .. && npm start → http://localhost:3001

Full UI works in Dev-Mock mode — no Docker needed.

Option B — Docker Stack
$ docker compose up -d Traefik → :80 / :8080 Cyber Lab → :3001 PostgreSQL → :5432 Redis → :6379

Full production stack with auto-healing and reverse proxy.

Option C — LAN Wi-Fi
$ npm start → http://192.168.x.x:3001 # Any device on same network # Zero config needed

Perfect for classroom and team training sessions.

Option D — Kubernetes
$ kubectl apply -f k8s/ $ kubectl get pods -n cyberrange # Scale to 100s of concurrent # operators with HPA

Enterprise-scale deployment with Kubernetes orchestration.

Security Architecture

Built for Security — From Day One

🔐
Dynamic Flags

HMAC-SHA256 Signing

Each session flag = HMAC(sessionId + labId, SECRET). Server validates before awarding completion. No flag sharing between operators.

🏰
Container Isolation

Per-Session Sandbox

Each operator gets a dedicated Docker container in an isolated bridge network. Containers are automatically pruned on session end — zero persistence by design.

🛡
Session Security

UUID Session IDs

All session IDs are UUIDs — no sequential enumeration. WebSocket connections require a valid session UUID in the URL path. Sessions expire on TTL.

⚡
Rate Limiting

Redis-Backed Protection

Redis-backed rate limiting on session creation endpoints prevents container farm abuse. Keyspace expiry events handle automatic session cleanup.
